# YT 字幕译

只做一件事：把 YouTube 的英文字幕变成能一眼看懂的中文双语字幕。为 Lex Fridman、Joe Rogan 这类三小时长访谈和科技播客调过参数。

## 安装

1. Chrome 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选中 `C:\Users\001\yt-sub-translate` 这个文件夹
4. 点插件图标 → 右下角「设置」→ 填 API 地址、Key、模型
5. 点「测试连接」，看到绿色的样例译文就通了

## 用法

- 打开任意 YouTube 视频，**自动识别原声语言**，与目标语言不同就自动开启
- 播放器右下角多了个「译」按钮，随时开关（快捷键 `Alt+Shift+T`）
- 插件图标弹窗里可以随时切 **推理强度：关闭 / 低 / 中**，切完立刻对后续批次生效
- **拖动字幕框**：鼠标移到字幕框上会浮出三个手柄——左侧圆点拖位置，左右两条竖线拖宽度，双击任意手柄复位。位置和宽度都按播放器百分比保存，切到全屏 / 剧场模式也跟着走
- **选中复制**：框里的文字可以直接选；选中期间字幕暂停刷新（框边会亮一圈浅粉），松开选区自动恢复
- 弹窗里只留最常动的：总开关、推理强度、字号。显示方式 / 字体 / 底色 / 位置复位都在设置页

## 推理强度怎么选

| 档位 | 什么时候用 |
| --- | --- |
| **关闭** | 默认。字幕翻译基本够用，最快最省 |
| **低** | 长句、双关、技术梗多的对谈 |
| **中** | 明显更慢更贵，只在实在听不懂的段落临时开 |

设置页的「推理参数写法」决定用哪种参数名发给服务商：

- **`reasoning_effort` 含 `"none"`（默认，GPT-5 系列）** —— 三档都真发出去，「关闭」才是真关闭
- `reasoning_effort`，关闭时不发该字段 —— 最保守的兼容写法。注意：**不发字段 ≠ 不推理**，模型会退回它自己的默认档，既慢又贵，只在服务商拒收 `"none"` 时才用
- `enable_thinking` —— 通义 / DeepSeek 风格
- 从不发送 —— 模型不支持推理参数时用

**请求报 400 时，先来这里换一种写法。**

## 换模型

默认 `gpt-5.6-luna`。换代只改设置页「模型」一栏即可，同档次的新模型不需要动别的设置。当前默认值是按这一档模型调的：

- 推理参数默认走 `"none"` 显式关闭，而不是省略字段
- 每批 20 句 / 1500 字符（这类模型在长批次上格式依然稳，批次越大系统提示被摊得越薄）
- 并发 3，拖进度条后追字幕更快
- 系统提示告诉模型「这是一整场主播与嘉宾的连续对话」，让它保持口语语气、不要把闲聊翻成书面语

## 省 token 的几件事

都是默认开着的：

1. **整句合并再翻**。YouTube 的字幕一条只有两三个词，直接翻既贵又碎。插件把整轨拼成一条文本、按字符位置插值时间轴，切成完整句子再送翻译。行数少了，质量反而更高。
2. **只翻你看到的部分**。默认只翻译播放头之后 45 句（约 4~5 分钟）。三小时的播客你看了二十分钟，就只花二十分钟的钱。
3. **结果缓存到本地**。见下面「缓存」一节。
4. **极简输出格式**。用 `序号|译文` 的纯文本而不是 JSON，省掉大量结构字符。
5. **上下文只带一句**。每批附带上一句原文（约 30 token）保证连贯，不做长上下文堆叠。

想更省：把「每批句数」调大（提示词被摊薄）、把「预翻译句数」调小、关掉上下文。
想更准：把推理强度提到「低」、保持上下文开启。

## 字体

设置页三选一，都用系统自带字体，不额外下载：

| 选项 | 字体栈 | 什么时候用 |
| --- | --- | --- |
| **雅致衬线**（默认） | Georgia + 思源宋体 | 衬线字形有呼吸感，长视频看着不累 |
| 现代无衬线 | Inter / Segoe UI + 思源黑体 | 笔画最实，小字号或低画质视频下最稳 |
| 书卷楷体 | Constantia + 楷体 | 最有手写味道，但笔画细，建议配更大字号和更深底色 |

原文和译文**颜色深度完全一致**（都是纯白 + 同样的投影），只靠字号分主次，默认原文是译文的 0.8 倍。设置页里有实时预览，背景是模拟视频画面的灰调渐变，方便判断底色深度够不够。

## 语言

**源语言全自动，不用设置。** 插件从视频的字幕轨列表里自己判断原声语言：自动字幕（ASR）一定是按原声语言生成的，所以它是最可靠的语言判据；但人工字幕有标点、质量更好，所以同语言时优先用人工轨。英文、日文、德文、西班牙文……只要 YouTube 有字幕轨就能翻。

**目标语言默认 `auto`，跟随浏览器界面语言**，也不用设置。想固定成别的，在设置页直接写语言名（`简体中文` / `繁體中文` / `English` / `日本語`…）。

原声语言和目标语言一致时（比如中文视频、中文界面），**不会自动开启翻译**，弹窗会显示「原声已是目标语言，无需翻译」。想强行翻还是可以手动点播放器上的「译」按钮。

切句是按**显示宽度**算的，中日韩和全角字符按 2 个单位、其余按 1 个——130 个拉丁字符和 65 个汉字，无论信息量还是屏幕宽度都差不多，所以同一套长度上限在各语种下都成立。中日韩之间不会被插入空格，断句认全角标点（`。！？，、；：`），没有空格可依时按宽度硬切。

## 缓存

翻译结果存在 `chrome.storage.local`，那是磁盘上的持久存储：**刷新页面、关标签、关浏览器、重启电脑都不会丢**。同一个视频重看、拖回去重听，一个 token 都不会再花。

- 默认保留 **60 天**、最多 **300 个视频**（设置页可调到 1 年 / 1000 个）
- 「保留天数」按**最后一次看过**算，不是按第一次翻译的时间——常看的视频不会被当成旧数据清掉
- 清理走一份单独的 `cacheIndex` 索引，只读时间戳、不把所有缓存正文加载进内存
- 缓存按「视频 + 模型 + 译文语言」区分，所以换模型或换目标语言会重新翻
- 扩展声明了 `unlimitedStorage`，不受默认约 10MB 配额限制。一期三小时的播客大约 100KB，300 期也就 30MB 左右
- 设置页「数据」一栏能看到已缓存多少个视频、占多少磁盘、最早一条多久没用过

## 字幕长度（决定字幕框会有多高）

这是「一屏几行」的总开关，设置页三选一：

| 档位 | 切句上限 | 效果 |
| --- | --- | --- |
| 紧凑 | 96 字符 | 中英大多各占一行，框最矮。代价是长句在逗号处多切几刀，译文偶尔略碎 |
| **标准**（默认） | 130 字符 | 完整句子优先，长句才切。通常英文一到两行、中文一行 |
| 完整 | 180 字符 | 几乎不拆句，译文最连贯，但可能到四行，框明显变高 |

改这个档位会重新切句，但缓存是按**原文哈希**存的，没变的句子仍然直接命中，只有边界变了的句子需要重翻。

## 字幕框的宽度

框宽**贴合内容自动伸缩**：短句只占一小条，长句一路撑到上限才折行——尽量往两边长，而不是往下堆。

上限默认画面宽度的 **88%**，两种改法：

- 设置页「字幕框最大宽度」滑块，20%~96%
- 直接在视频里**拖字幕框的左右边缘**（鼠标移上去会浮出两条竖线），双击边缘复位

嫌框太高就把这个值调大，长句折行会明显变少。

**框宽按真正折出来的行收紧**：CSS 的 `max-content` 是按「不折行时的宽度」算的，英文长句折了两行、框却仍然撑到上限，中文短句左右就空出一大片黑边。所以渲染后会用 `Range.getClientRects()` 量出每一行的实际宽度，按最宽那行把框收回来。换行同时用了 `text-wrap: balance`，两行长度拉均匀，不会出现第二行只剩一两个词的碎尾。

拖边缘时框会实际展开到你拖的宽度（否则边缘跟不住光标），松手后收回贴合内容——拖出来的是**上限**，不是当前宽度。

## 不被进度条压住

字幕框底部间距由 JS 按 `.ytp-chrome-bottom` 的实际高度算出，控制栏弹出时字幕自动上移、收起时落回，全屏和普通模式都是量出来的而不是写死的。

如果你把字幕框拖到了自定义位置，控制栏弹出时会用位移把它顶上去，**保存的位置本身不变**，收起后自己落回原处。

字号滑块范围 14~64，默认 24。**全屏时字号会按播放器高度自动放大**（以 620px 高为基准，最多 2.8 倍，只放大不缩小），所以滑块上的数字是「小窗口下最小会是多大」。不想要这个行为可以在设置页关掉「字号随画面大小放大」。

## 中英不同步是怎么修的

症状：中文把后面几句的内容提前说完了，接着好几行英文一句译文都没有。

根因不在时间轴，在切句和容错两处：

1. **切句切出了半截片段**。原先长句会在连词处硬切（“…they are doing something” / “that looks like reasoning…”），这种片段翻成中文必然要跨行调语序，模型就把相邻几行并成一整句塞进第一行，后面留空。现在**只在强标点（逗号 / 分号 / 破折号）处切**，且只有超过 155 字符才切——一句话尽量保持完整，作为一个翻译单元。100~155 字符的句子就让它在屏幕上折成两行，也不拆。
2. **模型少还了行，代码完全没补救**。现在每批**在批内重新编号 1..N**（数字短、更省 token，也比四位数的全局序号不容易错位），拿回结果后逐行核对；**缺哪几行就单独再发一次补翻请求**，只发缺的那几行。两次都没回来的行不再挂着省略号干等，直接只显示原文。
3. 顺带修了两个时间轴上的隐患：自动字幕的 cue 时长常常盖过下一条（播放器靠它做滚动效果），不修掉按字符插值出来的时间会整体偏晚，现在把每条 cue 的结束时间夹到下一条开始；每句字幕也会**一直留到下一句开始**（静音处最多多留 1.2 秒），不会一闪就没。

## 一些实现细节

- 字幕来源优先走**同源直接拉取** `captionTracks[].baseUrl`（不动你的字幕开关）；失败时兜底**程序化打开原生字幕**、由注入脚本劫持 `/api/timedtext` 请求截获数据。
- 自动字幕的 `aAppend` 滚动重复帧会被丢弃，避免同一句翻两遍。
- 翻译请求走 background service worker 发出，绕过页面 CORS。
- API Key 存在 `chrome.storage.local`，不同步、不外发。

## 已知限制（v0.1）

- 直播视频（滚动字幕）不支持
- 依赖 YouTube 已有的字幕轨；完全没有字幕的视频不做语音识别
- 无空格语言（中日泰）在没有标点可切时只能按宽度硬切，可能切在词中间
- 兜底方案会打开你 YouTube 的原生字幕开关（插件会用 CSS 隐藏它避免重影，关掉翻译后它会重新出现）

## 文件结构

```
manifest.json        扩展清单
common.js            默认配置 + 读写设置
background.js        翻译请求、用量统计、快捷键
content/
  inject.js          主世界脚本：劫持 timedtext、读播放器信息
  content.js         切句、懒调度、叠加层渲染、播放器按钮
  overlay.css        字幕与按钮样式
popup/               弹窗（开关、推理强度、显示）
options/             设置页（API、省 token、外观、数据）
icons/make-icons.js  图标生成脚本（node icons/make-icons.js）
```
