# Sub Translator

自动识别原声语言，把 YouTube 的字幕译成你一眼看懂的那一种，默认双语对照。为 Lex Fridman、Joe Rogan 这类三小时长访谈和科技播客调过参数。

## 安装

1. `npm install && npm run build`（内容脚本要打包一次，见下面「开发」）
2. Chrome 打开 `chrome://extensions/`
3. 右上角打开「开发者模式」
4. 点「加载已解压的扩展程序」，选中仓库里的 **`dist`** 文件夹
5. 装好会自动打开设置页 —— 填 API 地址、Key、模型
6. 点「测试连接」，出现一张写着「已连通」的模型卡就通了

改完代码要重新 `npm run build`，再去扩展页点一下刷新。`npm run zip` 出的是
`build/sub-translator-<版本>.zip`，可以直接上传商店或者发给别人。

## 用法

- 打开任意 YouTube 视频，**自动识别原声语言**，与目标语言不同就自动开启
- 播放器右下角多了个「译」按钮，随时开关（快捷键 `Alt+Shift+T`）
- 插件图标弹窗里可以随时切 **推理强度：关闭 / 低 / 中**，切完立刻对后续批次生效
- **拖动字幕框**：鼠标移到字幕框上会浮出三个手柄——左侧圆点拖位置，左右两条竖线拖宽度，双击任意手柄复位。位置和宽度都按播放器百分比保存，切到全屏 / 剧场模式也跟着走
- **选中复制**：框里的文字可以直接选；选中期间字幕暂停刷新（框边会亮一圈浅粉），松开选区自动恢复
- 弹窗里只留最常动的：总开关、推理强度、字号；点推理强度右边的模型名可以直接换配置档。显示方式 / 字体 / 底色 / 位置复位都在设置页

## 推理强度怎么选

| 档位 | 什么时候用 |
| --- | --- |
| **关闭** | 默认。字幕翻译基本够用，最快最省 |
| **低** | 长句、双关、技术梗多的对谈 |
| **中** | 明显更慢更贵，只在实在听不懂的段落临时开 |

设置页的「推理参数写法」决定用哪种参数名发给服务商：

- **`reasoning_effort` 含 `"none"`（默认，GPT-5 系列）** —— 三档都真发出去，「关闭」才是真关闭
- `reasoning_effort`，关闭时不发该字段 —— 最保守的兼容写法。注意：**不发字段 ≠ 不推理**，模型会退回它自己的默认档，既慢又贵，只在服务商拒收 `"none"` 时才用
- `enable_thinking` —— 通义 / DeepSeek 风格
- 从不发送 —— 模型不支持推理参数时用

**请求报 400 时，先来这里换一种写法。**

选对没有不用猜：点设置页的**测试连接**，弹出的模型卡里并排摆着这次实际发出去的推理字段，和**模型真的烧了多少推理 token**。设成「关闭」却还在烧，卡片会直接标红告诉你写法选错了。服务商不回报推理用量时写「未回报」，不会拿 0 冒充。

## 接口配置档

设置页「模型与接口」顶上是配置切换。一套服务商就是一档，存着**地址、Key、模型、译文语言、推理参数写法**这五项，随时切。改这五项时会自动存回当前那一档，不用手动保存。

- **新建** 建一份干净的（不会带上一档的 Key），建完直接进重命名
- **复制** 整档复制一份，适合「同一家、换个模型」
- **删除** 要点两下，第二下才真删；只剩一档时删不掉

**换档不用跑设置页**：弹窗里「推理强度」右边写着当前模型，点它就列出所有配置档，
点一下就切过去；最后一条「管理配置…」才回设置页做新建 / 复制 / 重命名 / 删除。

其余设置（外观、缓存、省 token）是全局的，不随配置走。切换配置会让已经翻好的字幕作废重翻 —— 换了模型就是另一套译文，缓存键里本来就带着模型名。

老版本升级上来不用做任何事：第一次打开设置页会拿你当前的设置原地立一档「默认」，一个字段都不会改。

## 换模型

默认 `gpt-5.6-luna`。换代只改设置页「模型」一栏即可，同档次的新模型不需要动别的设置。当前默认值是按这一档模型调的：

- 推理参数默认走 `"none"` 显式关闭，而不是省略字段
- 每批 20 句 / 1500 字符起步，翻顺了会自己涨到 30、40 句（见下面「省 token」第 6 条）
- 并发 3，拖进度条后追字幕更快
- 系统提示告诉模型「这是一整场主播与嘉宾的连续对话」，让它保持口语语气、不要把闲聊翻成书面语
- 视频标题也一并给模型（框架文字 20 token，加上标题本身常见是 25~40）。同一个 agent / trait / model，在 AI 播客里和在 Rust 教程里根本不是一回事，光看一批二十句常常判断不出领域

## 省 token 的几件事

全都是自动的，设置页里没有对应开关 —— 这几条没有「要不要开」的余地：

1. **整句合并再翻**。YouTube 的字幕一条只有两三个词，直接翻既贵又碎。插件把整轨拼成一条文本、按字符位置插值时间轴，切成完整句子再送翻译。行数少了，质量反而更高。
2. **只翻你看到的部分**。默认只翻译播放头之后 45 句（约 4~5 分钟）。三小时的播客你看了二十分钟，就只花二十分钟的钱。
3. **结果缓存到本地**。见下面「缓存」一节。视频自带目标语言人工字幕时更省——整场一个 token 都不花，见「视频自带中文字幕就直接用」。
4. **极简输出格式**。用 `序号|译文` 的纯文本而不是 JSON，省掉大量结构字符。
5. **上下文按预算给，不堆叠**。每批前面带几句已经翻过的「原文 → 译文」（模型看得见自己上一批把 agent 译成了什么，术语和人称才跨批一致），约 110 token；后面再带下一批的开头原文，约 65 token，**但只发给没有标点的轨** —— 有标点时句子是按 `[.!?。！？]` 切的，批尾那一句本来就完整，给了也帮不上忙，跟下面第二节那两句 ASR 提示同一个道理。两块都按字符预算裁，超了从远的一头砍。这一项和上面的缓存都没有开关——关掉只会更贵更难看。
6. **批次会自己变大**。系统提示词约 250 token，是按「请求次数」付的 —— 一批 20 句时它占整个输入的四成。所以批次不写死：从 20 句起步，连续三批模型都逐行对齐无误就升一档（30 句、40 句），任何一批出现错位立刻回落，并且这一档从此不再试。批次大了模型能看到的上下文也更多，术语和语气反而更统一。
7. **拖进度条时不翻**。播放头一次跨过 5 句以上就认定是在拖动，停稳 1.2 秒才开始调度。以前是落到哪就立刻按并发数翻哪，从头拖到尾能白白发出十来个请求 —— 而那些内容一句都没被看到。

还剩两个真正会影响花费的旋钮，都在设置页里：

- **推理强度**（弹窗里那三个按钮）。从「关闭」提到「低」，输出 token 可能翻几倍，翻译质量提升有限。字幕基本用不上。
- **字幕长度**（紧凑/标准/完整）。译文短，输出 token 就少，而输出的单价通常是输入的几倍。但它是靠把话说短来省钱的，在意译文质量就别动它。

## 对齐统计

设置页底下那行除了 token 用量，还会写「翻了 N 批，错位 X 批（Y%），拆块 Z 次，补翻 W 行」。

这行是拿来回答一个具体问题的：**改了提示词或上下文之后，模型的逐行对齐是变好了还是变差了。** 译文好不好没法自动判，但错位有客观指纹——拆过块、留了空、最后放弃了几行，这三样代码本来就知道，只是以前没人记下来。想比较两套配置，就翻同一个视频两遍，中间只改那一项，看这行数字。

跟对齐无关的失败不算进去：401、网络中断这些一次就能把错位率顶到 100%，记进来这个数就没法看了。反过来，服务商不回报 `usage` 时对齐的账照记——恰恰是那种时候更需要它。

## 字体

设置页三选一，都用系统自带字体，不额外下载：

| 选项 | 字体栈 | 什么时候用 |
| --- | --- | --- |
| **雅致衬线**（默认） | Georgia + 思源宋体 | 衬线字形有呼吸感，长视频看着不累 |
| 现代无衬线 | Inter / Segoe UI + 思源黑体 | 笔画最实，小字号或低画质视频下最稳 |
| 书卷楷体 | Constantia + 楷体 | 最有手写味道，但笔画细，建议配更大字号和更深底色 |

原文和译文**颜色深度完全一致**（都是纯白 + 同样的投影），只靠字号分主次，默认原文是译文的 0.8 倍。设置页里有实时预览，背景是模拟视频画面的灰调渐变，方便判断底色深度够不够。

## 语言

**源语言全自动，不用设置。** 插件从视频的字幕轨列表里自己判断原声语言：自动字幕（ASR）一定是按原声语言生成的，所以它是最可靠的语言判据；但人工字幕有标点、质量更好，所以同语言时优先用人工轨。英文、日文、德文、西班牙文……只要 YouTube 有字幕轨就能翻。

**在 YouTube 的字幕菜单里换语言，翻译框会跟着换。** 插件一边盯着播放器当前选中的字幕轨、一边劫持字幕请求 —— 两条路是因为同一条轨再选回来时播放器往往直接吃自己的缓存、根本不发请求。换轨之后旧译文立即作废、按新轨重新切句重翻，原声语言也跟着改。如果你选的那条轨本来就是目标语言，插件会自动让位给 YouTube 自己的字幕，不再花钱重翻一遍。

**弹窗里会写明现在拿哪条轨当原文、这个视频一共有哪些轨，以及缺的是哪种语言。** 有些视频压根没有原声语言那条轨 —— 比如游戏实况的过场动画，对白是游戏自己烧进画面的，YouTube 上只挂了别的语言的字幕。这时插件只能退回现有的轨去翻，等于翻「译文的译文」；在字幕菜单里怎么点也切不到原声语言，因为那条轨根本不存在。弹窗会直说「没有 English 字幕轨，只能拿现有的轨当原文」，免得让人以为是切换没生效。插件不做 OCR、也不做语音识别，画面里烧死的字幕取不到。

另外，播放器有时会抢先拉回一条不是原声语言的轨（账号开了自动翻译，或者视频默认轨就不是原声）。插件自己点名要的那条轨会盖过它，不会将错就错。

**目标语言默认 `auto`，跟随浏览器界面语言**，也不用设置。想固定成别的，在设置页直接写语言名（`简体中文` / `繁體中文` / `English` / `日本語`…）。

原声语言和目标语言一致时（比如中文视频、中文界面），**不会自动开启翻译**，弹窗会显示「原声已是目标语言，无需翻译」。简体和繁体算同一种语言，两边都不会翻。想强行翻还是可以手动点播放器上的「译」按钮。

## 音轨：AI 配音换回原声

多音轨视频（人工配音，或 YouTube 的 AI 自动配音）常常一上来就给你一条配音轨，听着别扭。插件**盯着播放器当前选中的音轨**（每秒问一次 `getAudioTrack()`），换轨立刻跟上：

- 换到中文音轨（配音也算）→ 没什么可翻的，**自动停下**，弹窗写「当前是配音音轨，无需翻译 · 换回原声音轨就会自动翻译」
- 换回英文原声 → **自动接着翻**，不用自己再点一次
- 你自己手动关掉的翻译不会被这套逻辑打开——关了就是关了

判断音轨语言时以**正在放的那一条**为准，而不是播放器信息里的第一条：多音轨视频里那两者经常不是一回事。音轨语言比字幕轨语言更有发言权——放着中文配音、字幕轨列表里却挂着英文自动字幕，是很常见的组合。

## 视频自带中文字幕就直接用

视频自带一条目标语言的**人工**字幕轨时，那就是一份现成的译文，没有理由再花钱翻一遍。插件会自动取来，贴到自己切好的句子上：**双语、字体、拖动、选中复制全都照旧，只是「译文」这一半不来自模型，一个 token 都不花。**

- 自动字幕（`asr`）不算——那是机器听写原声的，只会是原声语言
- 同时有简体和繁体时按目标语言挑：目标是简中就优先 `zh-Hans` / `zh-CN`；只有繁体也会用（简中用户看得懂）
- 全程不需要你去 YouTube 的字幕菜单里操作，菜单里的选择也不会被改动
- 两条轨的断句边界几乎不可能一致，所以按「这条 cue 的时间大部分落在哪一句里」归属，**一条 cue 只算给一句**，不会同一行中文在相邻两句里各出现一次
- 贴不住的句子只显示原文；**贴合率低于 75%**（自带轨只有片头几分钟、或者时间轴对不上）就放弃这条轨，改回自己翻——正常的自带轨贴合率在 95% 以上
- 弹窗会写明「译文用的是视频自带的简体中文字幕，没花 token」

**想强制让模型重翻**：在 YouTube 的字幕菜单里选英文（或任何别的语言）那条轨——插件认下你的选择当原文，照常翻译。

切句是按**显示宽度**算的，中日韩和全角字符按 2 个单位、其余按 1 个——130 个拉丁字符和 65 个汉字，无论信息量还是屏幕宽度都差不多，所以同一套长度上限在各语种下都成立。中日韩之间不会被插入空格，断句认全角标点（`。！？，、；：`），没有空格可依时按宽度硬切。

## 缓存

翻译结果存在 `chrome.storage.local`，那是磁盘上的持久存储：**刷新页面、关标签、关浏览器、重启电脑都不会丢**。同一个视频重看、拖回去重听，一个 token 都不会再花。

- 默认保留 **60 天**、最多 **300 个视频**（设置页可调到 1 年 / 1000 个）
- 「保留天数」按**最后一次看过**算，不是按第一次翻译的时间——常看的视频不会被当成旧数据清掉
- 清理走一份单独的 `cacheIndex` 索引，只读时间戳、不把所有缓存正文加载进内存
- 缓存按「视频 + 模型 + 译文语言」区分，所以换模型或换目标语言会重新翻
- 扩展声明了 `unlimitedStorage`，不受默认约 10MB 配额限制。一期三小时的播客大约 100KB，300 期也就 30MB 左右
- 设置页「数据」一栏能看到已缓存多少个视频、占多少磁盘、最早一条多久没用过

## 恢复默认

设置页最后一栏「恢复默认」把所有设置改回出厂值，缓存和用量统计不动（那两样各有自己的按钮）。

- 默认勾着**保留模型与接口**：地址、Key、模型、译文语言、推理写法和所有配置档原样留下，只有外观、缓存规则、字幕框位置回到默认
- 取消勾选则连接口一起出厂：配置档只剩一档空的「默认」，**Key 会被清掉**
- 按钮点第一下只是变成「确认恢复？」，3 秒内再点一下才真执行

## 字幕长度（决定字幕框会有多高）

这是「一屏几行」的总开关，设置页三选一：

| 档位 | 切句上限 | 效果 |
| --- | --- | --- |
| 紧凑 | 96 字符 | 中英大多各占一行，框最矮。代价是长句在逗号处多切几刀，译文偶尔略碎 |
| **标准**（默认） | 130 字符 | 完整句子优先，长句才切。通常英文一到两行、中文一行 |
| 完整 | 180 字符 | 几乎不拆句，译文最连贯，但可能到四行，框明显变高 |

改这个档位会重新切句，但缓存是按**原文哈希**存的，没变的句子仍然直接命中，只有边界变了的句子需要重翻。

## 字幕框的宽度

框宽**贴合内容自动伸缩**：短句只占一小条，长句一路撑到上限才折行——尽量往两边长，而不是往下堆。

上限默认画面宽度的 **88%**，两种改法：

- 设置页「字幕框最大宽度」滑块，20%~96%
- 直接在视频里**拖字幕框的左右边缘**（鼠标移上去会浮出两条竖线），双击边缘复位

嫌框太高就把这个值调大，长句折行会明显变少。

**框宽按真正折出来的行收紧**：CSS 的 `max-content` 是按「不折行时的宽度」算的，英文长句折了两行、框却仍然撑到上限，中文短句左右就空出一大片黑边。所以渲染后会用 `Range.getClientRects()` 量出每一行的实际宽度，按最宽那行把框收回来。换行同时用了 `text-wrap: balance`，两行长度拉均匀，不会出现第二行只剩一两个词的碎尾。

拖边缘时框会实际展开到你拖的宽度（否则边缘跟不住光标），松手后收回贴合内容——拖出来的是**上限**，不是当前宽度。

## 不被进度条压住

字幕框底部间距由 JS 按 `.ytp-chrome-bottom` 的实际高度算出，控制栏弹出时字幕自动上移、收起时落回，全屏和普通模式都是量出来的而不是写死的。

如果你把字幕框拖到了自定义位置，控制栏弹出时会用位移把它顶上去，**保存的位置本身不变**，收起后自己落回原处。

字号滑块范围 14~64，默认 24。**全屏时字号会按播放器高度自动放大**（以 620px 高为基准，最多 2.8 倍，只放大不缩小），所以滑块上的数字是「小窗口下最小会是多大」。不想要这个行为可以在设置页关掉「字号随画面大小放大」。

## 中英不同步是怎么修的

症状：中文把后面几句的内容提前说完了，接着好几行英文一句译文都没有。

根因不在时间轴，在切句和容错两处：

1. **切句切出了半截片段**。原先长句会在连词处硬切（“…they are doing something” / “that looks like reasoning…”），这种片段翻成中文必然要跨行调语序，模型就把相邻几行并成一整句塞进第一行，后面留空。现在**只在强标点（逗号 / 分号 / 破折号）处切**，且只有超过 155 字符才切——一句话尽量保持完整，作为一个翻译单元。100~155 字符的句子就让它在屏幕上折成两行，也不拆。
2. **模型少还了行，代码完全没补救**。现在每批**在批内重新编号 1..N**（数字短、更省 token，也比四位数的全局序号不容易错位），拿回结果后逐行核对；**缺哪几行就单独再发一次补翻请求**，只发缺的那几行。两次都没回来的行不再挂着省略号干等，直接只显示原文。
3. 顺带修了两个时间轴上的隐患：自动字幕的 cue 时长常常盖过下一条（播放器靠它做滚动效果），不修掉按字符插值出来的时间会整体偏晚，现在把每条 cue 的结束时间夹到下一条开始；每句字幕也会**一直留到下一句开始**（静音处最多多留 1.2 秒），不会一闪就没。

## 自动字幕（没有人工字幕的视频）

有人工字幕就用人工的（有标点、质量更好），这一步一直是自动的。但不少视频只有自动字幕，那种轨**没有标点、没有大写、偶尔会听错词**，翻译质量确实会掉一档。做了两件事把差距补回来：

**一、不再按 cue 边界切句。** YouTube 的自动字幕一条 cue 只有两三个词，而 cue 边界只是「每两三个词换一屏」的显示节奏，跟语义毫无关系。以前检测不到标点时就拿它当句子边界，于是每一句都被切在半截上：

```
修复前（7 段，平均 33 字符）        修复后（2 段，平均 117 字符）
so the question I keep coming     so the question I keep coming back to is what
back to is what intelligence      intelligence really is and whether we would
really                            even recognise it
is and whether we would even      if we saw it in a machine because the definitions
recognise it if we saw it in a    we have are circular and honestly not very useful
machine                           when you try to apply them
...
```

现在只在**真的停顿了**的地方断开（相邻 cue 的时间差超过 0.45 秒）。滚动字幕的 cue 首尾严格相接，所以 gap 只会出现在真实的静音处。断不开的长句交给原有的长度切分，它会优先切在 `and` / `because` / `so` 这些连词前。

模型拿到的从半截短语变成完整从句，译文自然通顺得多；顺带行数少了一半以上，token 也省了。

**二、告诉模型这是识别出来的文本。** 只在原文确实没有标点时，系统提示会额外加两句：让它自己判断句子结构并给译文补上标点；上下文能明确看出是听错的词就按本意翻，看不出就照原样翻，不许瞎猜。有标点的轨不加这几句，不白花 token。

判据是「这一轨有没有标点」而不是「是不是 ASR 轨」——有些自动字幕带标点（不需要提示），有些人工上传的反而不带（需要）。

## 一些实现细节

- 字幕来源优先走**同源直接拉取** `captionTracks[].baseUrl`（不动你的字幕开关）；失败时兜底**程序化打开原生字幕**、由注入脚本劫持 `/api/timedtext` 请求截获数据。
- 自动字幕的 `aAppend` 滚动重复帧会被丢弃，避免同一句翻两遍。
- 没有标点的字幕轨按停顿（>0.45 秒静音）分组，而不是按 cue 边界，见上面「自动字幕」一节。
- 翻译请求走 background service worker 发出，绕过页面 CORS。
- API Key 存在 `chrome.storage.local`，不同步、不外发。

## 已知限制

- **正在直播的视频不支持**（字幕是一边生成一边推的，跟「整轨拉下来切句」这套做法对不上）。
  弹窗会直说，不会让你干等。直播结束后的录播照常翻。
- **Shorts 不支持**（页面上没有我们认得的播放器），同样会直说。
- 依赖 YouTube 已有的字幕轨：完全没有字幕的视频不做语音识别。
- 无空格语言（中日泰）在没有标点可切时只能按宽度硬切，可能切在词中间。
- 兜底方案会打开你 YouTube 的原生字幕开关（翻译开着时用 CSS 藏起来，关掉翻译会原样还回去）。
- 界面只有简体中文和英文两种，跟随浏览器语言。
- 只支持 Chromium 系桌面浏览器；移动端、嵌入在别的网站里的播放器都不支持。

## 隐私

**这个扩展不收集任何数据**，没有任何东西发给作者或第三方。

- **API Key** 只存在本机浏览器（`chrome.storage.local`），不同步、不外发，只作为
  `Authorization` 头发给**你自己填的那个 API 地址**。
- **字幕文本** 只发给同一个地址，用于翻译；除此之外不发往任何地方。
- **译文缓存与用量统计** 只存本机，设置页可一键清空。
- **诊断信息** 只在你点「复制诊断」时生成，进的是剪贴板，里面不含 Key（只写「已填 / 空」），
  接口只留主机名，原文译文一个字都不带。

## 权限

| 权限 | 为什么要 |
| --- | --- |
| `storage` / `unlimitedStorage` | 存设置和译文缓存；长播客的缓存会超过 5 MB 默认上限 |
| `https://www.youtube.com/*` | 内容脚本要在视频页取字幕、画字幕框 |
| `https://api.openai.com/*` | 默认接口。填别的地址**不会**自动获得权限，要在设置页点「授权访问」 |
| `<all_urls>`（可选） | 只在填了自定义 API 地址时按需申请，安装时不索要 |
| `commands` | Alt+Shift+T 开关字幕 |

## 固定扩展 ID（可选）

「加载已解压」时 ID 是按目录路径算的：换台机器或换个目录，ID 变了，`chrome.storage`
里的设置、译文缓存、用量统计就都读不到了。想把 ID 定死就跑一次：

```
npm run keygen
```

它往 `manifest.json` 写一个公钥、把私钥放在 `build/extension-key.pem`（不进版本库）。
**代价是一次性的**：ID 当场就变，现在这个实例里已有的设置和缓存（缓存里是已经付过钱的
译文）从此读不到。所以它不是默认打开的 —— 挑准备发布、或者准备换机器的时候再跑。

## 测试

```
npm test           # 先打包，再跑全部测试文件
npm run lint       # eslint 最小规则集
npm run check      # lint + 测试
npm run e2e        # 端到端冒烟（真 Chrome + 真扩展，需先 npx playwright install chromium）
node test/state.test.js   # 单独跑一个（需要先 npm run build）
```

都用桩环境（假 chrome API + 假 DOM / 假 fetch）真实加载被测文件，不联网、不碰真实存储。
内容脚本的几个测试加载的是 `dist/content/content.js` —— 打包这一步本身也会出错，
拿源码去测就永远发现不了。

- `state.test.js` 覆盖状态机里几条出过问题的路径：切视频时的在途请求、上一个视频
  迟到的字幕、来路不明的字幕、字幕轨迟到、播放中改设置、整批错位时的报错、缓存键的
  区分度、重复原文的去重、视频没有原声语言那条轨、播放器抢先拉回别的语言，以及在
  YouTube 的字幕菜单里换语言这一整条链路（首份字幕还在路上时换也算数、只认自己
  点名要的那一次回应、语言对不上就不认、要不到就维持现状）。
- `segments.test.js` 覆盖切句与时间轴：长静音处下一句不能提前冒出来；无标点的自动字幕
  必须按停顿分组而不是按 cue 边界（段数、平均长度、一个字都不能丢），真的停顿了还是要断开，
  有标点的轨不受影响。
- `align.test.js` 加载 `background.js`，覆盖自动字幕的额外提示（只在没标点时加、补翻那次
  也要带上、不能挤掉原有的逐行对齐要求），以及「模型把相邻几行并成一句」导致的整体错位：
  缺口碰到首行/末行的识别、拆块重来、拆到头仍治不好就整块只显示原文、中间漏译仍走
  单独补翻、没编号的行一律不许拿去补洞；另外覆盖失败分级 —— API 错误不触发严格重问，
  暂时性状态码（408/425/429/5xx）重试一次，配置类（400/401/403/404/422）当场认输；
  另外覆盖对齐统计：拆块记成错位、补翻不算、401 一个字都不许记、服务商不回报 usage 时
  对齐的账照记、老 stats 里没有这几个键时从 0 起算而不是变成 NaN。
- `batching.test.js` 覆盖两条省 token 的路：批次连续翻顺了会升档（20 → 30 → 40 句）、
  后端报错位就回落并且从此不再试那一档、网络层的错误（如 429）不算数不该拖累批次大小；
  以及拖进度条时一个请求都不许发，停稳之后要照常补上。
- `profiles.test.js` 覆盖设置页的接口配置档：老用户升级时拿现有设置原地立一档（一个字段
  都不许改）、切换要把整档灌回 settings 且不碰全局设置、在卡片里改字段要存回当前那一档
  （切走再切回来不能丢）、新建不继承上一档的 Key、复制自动加序号、删除要点两下且最后
  一档删不掉、存储里的 active 失效时兜回第一档。
- `test/e2e/smoke.mjs` 是唯一在真浏览器里跑的：装上打包好的扩展，把 YouTube 页面和
  模型接口都换成假的，验四条 —— 冷启动能翻出字幕并装上播放器按钮、切视频不再翻上一个
  视频的句子、用户换字幕轨后跟着换、连撞三次 429 之后自己恢复。单元测试全绿也可能装不
  起来（manifest 路径写错、打包漏文件、内容脚本第一行就抛异常），这四条堵的是那个洞。
- `popup.test.js` 覆盖弹窗里点模型名切配置档这条路：菜单每档一条 + 「管理配置…」、
  切换要把整档灌回 settings 且不碰全局设置、要通知页面按新配置重来、点当前档是空操作
  （不重复发消息）、每次打开都重画。
- `reasoning.test.js` 覆盖「测试连接」报出来的推理真相：四种参数写法各自到底发了哪几个
  字段、推理 token 在 usage 里的三种回报位置都要认得、服务商不回报时必须是 `null` 而不是
  `0`（报 0 会把「设了关闭却还在推理」这个最该报的问题盖掉）。
- `adopt.test.js` 覆盖「不花钱的那两条路」：视频自带目标语言人工字幕时自动取来贴上、
  贴上之前和之后都一个 `translateBatch` 都不许发、简繁按目标语言挑、自动字幕轨不算、
  一条 cue 只能算给一句、自带轨只覆盖片头（贴合率不够）要回退到自己翻；以及换音轨 ——
  切到中文配音就停下且不再发请求、换回英文原声自动接着翻、用户手动关过的不许被它打开。
- `context.test.js` 覆盖参考上下文：视频标题进系统提示前先把方括号、竖线、换行抹平
  （标题是页面来的文本，原样插进去就能伪造出一个块头骗过模型）、前文带译文而后文只带
  原文、两块都不许带编号（编号是唯一的对齐凭据）、按字符预算裁但至少留一行、后文只发给
  没有标点的轨、补翻和格式重问一律不带参考块、拆块时两半互为前后文且后半段能拿到
  前半段刚翻好的译文。
- `boot.test.js` 专测刷新（冷启动）这条路，用假时钟把几十秒快进过去，并且把
  `content.js` 和 `inject.js` 装进同一个 window 让它们真的对话：播放器 20 秒后才就绪时
  仍然有人在问、设置比播放器信息晚到时不能拿 DEFAULTS 去判语言和自动开启、
  首次拉字幕失败之后会重来。四条用例都对修复前的代码是红的。
